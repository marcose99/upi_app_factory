# Operator Portal Control Contract

The operator portal exposes local-only controls for health, evidence,
download/export, validation, requirements intake, engineering execution,
portfolio runtime, scenario, lifecycle, and read-only evidence workflows.

Critical mutation controls are wrapped by a shared in-flight action guard:
requirements submission, plan generation, approval, engineering start/cancel,
download export, validation run, runtime start/restart/stop/stop-all, and
runtime approvals. The guard acquires a lock domain before request dispatch,
sets `aria-busy`, suppresses duplicate activation, disables conflicting
controls, restores labels in `finally`, and leaves unrelated read-only controls
available.

Lock domains:

- `engineering-run`: run create, plan, approve, execute, cancel.
- `runtime-version`: per-version runtime start, restart, stop.
- `runtime-global`: stop-all conflicts with all runtime mutations.
- `validation`: validation self-check mutation.
- `download-export`: governed local export.

The canonical public UI route is `/operator-ui/`. Startup health is gated on
`GET /health`; `GET /operator-portal/health` remains an intentional API
compatibility alias. Launcher output must print the verified `/operator-ui/`
URL only after health succeeds.

The executable manifest generated by
`scripts/build_portal_control_coverage_manifest.py` is source-derived from
HTML, JavaScript handlers, and FastAPI routes. Regex/string presence alone is
not treated as coverage; each entry references behavioral pytest evidence.
